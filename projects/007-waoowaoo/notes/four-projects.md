# 四个 AI 视频项目：我们的理解

整理日期：2026-09-11。固定研究版本和证据链接见[网页说明](../web/summary/README.md)。Pixelle 与 waoowaoo 已局部实测；火宝与 Toonflow 仅核对官方资料。

## 共同点与真正的差异

四者都可以通过文字表达创作意图，再调用语言、图像或视频模型。但产品还要保存中间结果、组织任务、提供修改入口和完成媒体处理，所以不能把它们理解成只在界面上有细微差异的通用驱动。

| 项目 | 主要工作对象 | 交互目标 | 我们的定位理解 |
| :--- | :--- | :--- | :--- |
| Pixelle-Video | 文案、旁白、分镜素材、字幕模板、成片 | 配置后完成一条短视频制作流程 | 适合图文解说、知识口播和模板化推广 |
| waoowaoo v0.5 | 项目资源、参考关系、资源版本、生成任务 | 围绕选中的素材提出要求，检查结果后继续创作 | 适合素材组织、参考图创作和逐步修改 |
| 火宝短剧 | 剧集、剧本、角色场景道具、分镜任务 | 按制作阶段推进，审核镜头并批量生成导出 | 适合需要明确阶段和剧集组织的短剧制作 |
| Toonflow | 原著事件、改编剧本、角色素材、生产节点 | 编剧与生产 Agent 配合画布进行创作 | 适合原著改编、分镜编排及短剧生产 |

模型可以复用，工作流程仍需专门实现。换模型主要改变素材由谁生成；从口播流程改成剧集工作台，则涉及数据结构、执行流程和用户控制点。

## 演示告诉了我们什么

Pixelle 实际把 Codex 提供的两张图片和三段文案，经过原生配音、字幕模板与合成，做成了 14.7 秒短片。图片配口播是这个样例的形式；应用还提供其他生成入口，但本次没有验证动态镜头、数字人等效果。

waoowaoo 实际导入了同样两张图和 Pixelle 成片，验证了原版画布、图片预览、视频播放和图片引用到助手。需求草稿没有发送，因此不能把导入的视频说成 waoowaoo 生成的，也不能据此判断其生成质量。

“先做明确的小目标，再逐步修改”是我们对 waoowaoo 交互方式的理解。小目标是每轮任务的范围，不等于只能做短片，也不是经实测得出的时长限制。

火宝与 Toonflow 在官方流程中更明确地组织长剧情需要的剧本、角色与分镜。当前 Toonflow 也有画布，因此不能简单用“有无画布”区分它与 waoowaoo。上述模块是否能稳定产出优质剧情和一致角色，需要另行运行验证。

## 原理与扩展方向

- Pixelle：Python / Streamlit 提供入口，服务连接模型，HTML 模板经 Playwright 渲染，FFmpeg 完成媒体处理。可扩展领域脚本、模板、素材检索和模型适配。
- waoowaoo：Web 工作区保存资源与版本，独立 Agent runtime 和任务系统组织生成，数据库及对象存储保存项目和媒体。可扩展行业素材模板、协作审核、检索及剪辑配音集成。
- 火宝：当前官方版本以 Nuxt / Hono、Mastra Agent、SQLite 和 FFmpeg 组织剧本改写、提取、分镜与镜头任务。可进一步验证批量审核、失败恢复与剧集复用。
- Toonflow：当前官方资料描述分层 Agent、原著事件提取、编剧 / 生产工作流、记忆和可编程模型适配。可进一步验证长剧情连续性、制作规则复用和外部编辑器衔接。

扩展方向是研究建议，不是已经实现或测试的能力。未在相同输入、模型和参数下比较四者的画质、速度、成本和角色一致性。
