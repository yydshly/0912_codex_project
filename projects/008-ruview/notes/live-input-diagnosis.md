# 用户走动但曲线不变：现场排查

研究版本仍为 `33a9e90896a691a3f98de042b463e5945178b87c`。2026-09-13，用户报告在真实环境中走动，但监测页没有变化。本次结论是：存在回放/实时模式混淆，同时本机 RSSI 输入长时间固定；没有证据说明这套布置已实现有效的人体活动检测。

## 查到的事实

1. 首次检查后端时，采集仍在进行：约 74.6 秒、148 个样本，最新读取与服务器时间只相差约 0.09 秒，但所有 RSSI 均为 −57 dBm，原版分类窗口方差为 0。后续这轮 180 秒共 355 个样本，仍全部 −57 dBm。
2. 浏览器实际选中的是 18:53 的历史记录，时间滑块停在 126.8 秒。该画面不接收当前动作变化。此前“跳到信号变化”的引导没有充分突出这一边界。
3. 切回实时后，上一轮已结束，因而重新启动一轮采集。两次界面状态均通过浏览器确认。
4. 绕过网页及本地解析器，直接查询 Windows `WlanQueryInterface` 的 `wlan_intf_opcode_rssi`：连续 12 次、约每 0.5 秒一次，均成功返回 −57 dBm。
5. 再查询 `wlan_intf_opcode_realtime_connection_quality`：本机返回 1 条链路。连续 8 次读取该链路的 `lRssi`，均为 −57 dBm，链路质量为 85%。没有将质量百分比转换为额外的“实测 RSSI”。

原生调用只做查询，没有主动扫描、断开网络、修改驱动或无线设置，也没有人为添加信号波动。原版算法和阈值未修改。

## 结论及限制

回放模式不能用于观察现在的动作，这是已确认的界面使用问题。另一方面，网页后端和 Windows 原生接口读到相同的恒定值，说明“没有动作变化”并不只是曲线没刷新；在这组输入上，原版方差/能量阈值分类器没有足够的信息判断走动。

重复调用系统接口的时间戳，只能证明程序重新读取，不能证明网卡每次都产生了新的物理测量。驱动缓存或更新策略、量化/平滑、路由器与人的几何位置等是可能原因，本次没有逐项区分，不能直接断言某个原因或硬件损坏。

用户的走动反馈应保留为失败线索；由于具体走动时段没有同步标注，且当时界面处于历史回放，不能计算漏检率或把所有记录标为走动。也不能因为切回实时，就声称问题已经完全解决。

## 已做的修正

- 历史按钮改为“历史记录（不实时）”；进入后显示醒目的“现在走动不会改变这段记录”提示及返回实时入口。
- 采集结束时显示“当前动作不会继续写入”和新一轮启动入口。
- 正在采集但 RSSI 连续 15 秒不变时，明确显示输入没有变化、不能据此判断用户是否走动。
- “最新读数”改为“最近读取”，避免将程序查询时间当作传感器测量新鲜度。
- 保留原始曲线、原版分类和历史实测文件，不为产生响应而调低阈值或生成数据。
