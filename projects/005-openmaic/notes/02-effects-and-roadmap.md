# 效果、使用场景与扩展方向

研究日期：2026-09-11。版本：1.0.1 / `d5be3933176247feebf4007f6e31e20b93871609`。效果依据官方素材和静态源码，应用与扩展部分是研究建议。

## 效果证据如何理解

| 证据层次 | 已知情况 | 不能由此推断 |
| :--- | :--- | :--- |
| 官方图片与动图 | 展示课件、实验、PBL 等课堂形态 | 所有输入都能生成同等质量内容 |
| 关键源码 | 生成、编排、播放、评分和编辑有具体模块 | 各模型、浏览器及配置组合均已验证 |
| 工程评估目录 | 存在白板、大纲语言、编排、PBL 等评估脚本 | 本研究跑过这些评估，或已证明教学有效 |
| 本次运行测量 | 未运行完整上游应用 | 不能报告生成费用、延迟、准确率或学习收益 |

官方素材见[项目效果展示](../README.md)与[图片来源](../assets/README.md)；评估入口见[固定源码 eval 目录](https://github.com/THU-MAIC/OpenMAIC/tree/d5be3933176247feebf4007f6e31e20b93871609/eval)。

## 一个适合本研究仓库的使用例子

以下是拟议流程，尚未实际生成：

1. 输入一份带固定源码引用的开源项目研究文档。
2. 生成“项目定位 → 核心能力 → 架构 → 一次请求的数据流”课程大纲。
3. 用幻灯片讲概念，用互动页面展示数据如何流转。
4. 学生追问某一模块，老师结合材料解释，助教补充例子。
5. 用选择题与简答题检查能否解释系统边界。
6. 人工检查知识、图示与引用后，导出给团队使用。

输入应是经过核验的研究材料。仅给出仓库名字，并不等于系统已经完整阅读或正确理解整个代码库。

## 场景匹配

| 方向 | 可使用已有能力 | 实际落地仍需补充 |
| :--- | :--- | :--- |
| 个人学习与论文导读 | 材料解析、讲解、追问、测验 | 对照原文核验重要结论 |
| 教师备课与科普 | 课件、白板、互动实验、编辑 | 教学目标、知识准确性和难度审核 |
| 企业产品培训 | 手册转课程、项目任务 | 材料更新、身份权限、课程版本与发布 |
| 角色与项目训练 | 多角色对话、PBL 里程碑 | 可观察的交付标准和人工反馈 |
| 教育产品开发 | DSL、生成、编辑、渲染与存储包 | 产品用户体系、业务接入和长期维护 |

这些匹配是功能适配分析，不能替代实际用户测试。

## 扩展路线建议

| 优先级 | 扩展方向 | 建议实现 | 判断是否有效 |
| :--- | :--- | :--- | :--- |
| 1 | 来源可追溯 | 在材料提取和搜索基础上，把知识点、答案和图表绑定页码或源码位置 | 引用是否指向支持结论的原文 |
| 1 | 教师审核 | 草稿、预览、问题标注、修改记录、审核与发布 | 人工修改量和发布后纠错数量 |
| 1 | 可靠测验 | 客观题规则判分；简答题明确量规；异常结果标记待复核 | 与人工评分的一致性及异常识别 |
| 2 | 可验证实验 | 接入已测试的学科计算模块，模型负责讲解和组织界面 | 数值、边界条件和交互行为正确 |
| 2 | 学习诊断与补课 | 知识点关联题目，跟踪错题与追问，调整后续内容 | 能否识别薄弱点并改善后测结果 |
| 2 | 组织内教学 | 用户、课程权限、班级、作业、成绩对接 | 授权隔离与真实业务闭环 |
| 3 | 成本与稳定性 | 按阶段选择模型、缓存媒体、失败页面独立重试 | 单课费用、失败恢复率和等待时间 |

路线是研究建议，不代表上游承诺或本项目已经实现。涉及多用户部署时，需结合上游[持久化说明](https://github.com/THU-MAIC/OpenMAIC/blob/d5be3933176247feebf4007f6e31e20b93871609/README.md)重新设计身份与隔离，不能把公开的开发令牌当作用户认证。

## 三个关键判断

**知识来源比角色数量更影响专业课程可信度。** 多个人设可能丰富解释角度，但不自动带来独立事实核验。

**互动代码能执行，不代表实验正确。** 应把核心计算与模型生成的界面拆开验证。

**教学反馈需要影响后续内容。** 若测验只展示分数而不改变学习路径，尚不能称为经过验证的自适应教学。
