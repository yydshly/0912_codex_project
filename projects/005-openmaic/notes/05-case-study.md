# 实际案例：用一堂互动课学会欧姆定律

**同一组材料，贯穿课件、讲解、白板、实验、讨论、测验与项目设计。** 本案例面向刚接触电路的学习者，目标是能计算电流、正确换算单位，并选出满足条件的电阻。建议体验约 10–15 分钟；这是演示安排，不是教学效果测量。

[互动案例运行说明](../web/README.md)；启动后打开本机地址 `http://127.0.0.1:8765/case.html`。

## 案例材料与任务

原创课程以欧姆定律 I = U / R 和电功率 P = UI = U² / R 为基础，使用理想恒定电阻模型，忽略电源内阻和温度变化。公式参考 [OpenStax Physics · Key Equations](https://openstax.org/books/physics/pages/19-key-equations)，讲义、数值、课件、角色话术与题目均为本研究编写。

贯穿例题：6 V 电压、300 Ω 电阻，得到 0.02 A = 20 mA，功率 0.12 W。最终任务：给定 6 V，选择电阻，使电流在 15–25 mA 内，且计算功率不超过 0.25 W。这里校验数学模型，不作为真实器件选型规范。

## 按顺序体验八种效果

| 环节 | 具体操作 | 可以看到的效果 |
| :--- | :--- | :--- |
| 1. 课程准备 | 阅读原始材料与预编写课程方案，进入课堂 | 同一主题被组织成解释、操作、检查与应用的顺序 |
| 2. 课件讲解 | 切换三页课件、播放字幕、开关重点，尝试朗读 | 官方组件实际渲染 Slide 数据；字幕推进时重点跟随变化；朗读使用浏览器 / 系统语音 |
| 3. 白板推导 | 一步步揭示公式、代入、换算、功率 | 展示讲解与板书配合；可以回退和重置 |
| 4. 参数实验 | 把 6 V / 300 Ω 改成 6 V / 600 Ω，再试 12 V / 300 Ω；分别记录 | 电流由 20 降至 10 mA；第二组电流 40 mA、功率 0.48 W；电路数值、曲线与实验表同步更新 |
| 5. 角色讨论 | 选择话题，点击下一位发言 | 老师、提问同学、助教接力；数值来自进入讨论或重开讨论时的实验条件 |
| 6. 课堂测验 | 完成单选、多选与数值题，提交并修改答案 | 明确规则即时判分，解释错误与单位换算；缺答不会提交 |
| 7. 项目任务 | 比较 220 Ω 与 330 Ω，写下理由并提交 | 实时检查电流与功率约束；330 Ω 约 18.18 mA、0.109 W，满足两项要求 |
| 8. 改课与导出 | 修改标题与讲解，回课堂；下载记录与课件数据 | 官方课件随数据改变；生成 Markdown 学习记录与三页 Slide JSON，也可打印当前页面 |

实验保留最近 20 组记录，作答、设计说明和课件修改保存在本浏览器。不是账号同步；浏览器禁用存储时会显示提示，仍可下载记录。导航“已查看”仅指访问记录，不表示掌握知识。

## 哪些是真实库能力，哪些是演示实现

| 层次 | 本次实现与边界 |
| :--- | :--- |
| 官方真实组件 | 使用 npm 正式发布的 `@openmaic/renderer 0.1.6`，由 `SlideCanvas` 渲染三页课件和元素高亮；用 `@openmaic/dsl 0.11.1` 验证对应场景结构 |
| 本案例原创实现 | 八环节导航、预设字幕播放、白板逐步呈现、SVG 电路与曲线、参数计算、角色脚本、规则评分、项目校验、浏览器保存和下载 |
| 外部可选能力 | 朗读请求浏览器 / 系统语音接口；可用声音与响应取决于用户环境，失败时保留字幕。这不是 OpenMAIC 的 TTS 服务 |
| 没有执行 | 上传解析、模型规划课程、实时多角色回答、LangGraph 导演、上游白板动作引擎、模型评分、AI 编写实验代码、Pro 对话改课、PPTX / MP4 出口 |

这是一份**接入真实课件组件的独立教学案例**，不是完整 OpenMAIC 部署，也不是“已由 AI 自动生成整门课”的证据。其余交互用于具体呈现上游各类课堂形态，不能把本案例的规则评分和脚本对话视为上游实现。

完整应用研究固定在 [d5be3933176247feebf4007f6e31e20b93871609](https://github.com/THU-MAIC/OpenMAIC/tree/d5be3933176247feebf4007f6e31e20b93871609)，该提交 renderer 源码标记 0.1.7；本案例实际安装的是 [npm renderer 0.1.6](https://www.npmjs.com/package/@openmaic/renderer/v/0.1.6)，两者不是同一制品。依赖版本与完整性记录在子项目的 package-lock.json。构建会汇总已安装生产依赖许可，官方素材保留原许可。

## 从“展示页面”到“教学运行”

这个案例能直观看到差别：实验数据会进入讨论，作答会产生反馈，项目提交会检查约束，修改课件数据会改变后续讲解。这些需要数据结构、状态与执行逻辑，无法仅靠更换页面样式完成。

当前连动由确定性程序实现。完整 OpenMAIC 进一步让模型生成内容与教学动作，并由导演、播放器与工作台驱动课程。通用模型和资料处理可以复用，但课程组织与互动执行仍需独立建设；并不能确认它和闭源 NotebookLM 底层实现相同。[同类对比](04-comparison.md)

## 验证与下一步

本次验证覆盖计算规律与边界、评分、状态恢复、导出记录、官方 DSL 校验以及官方组件的服务端实际渲染。静态资源、模块依赖和站内链接通过构建检查。未做浏览器自动化、截图、实际语音或移动端实测，完整结果见[网页验证记录](../web/validation.md)。

要验证完整生成链路，需要另行配置可调用模型，在上游应用输入这份材料，生成课程，再逐项比较课件、实验代码、测验与讨论；进一步测试 TTS、工作台和视频出口。当前没有这些配置，因此没有虚构生成耗时、费用或质量结果。
