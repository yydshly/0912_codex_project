# 我们的理解：预设来源与获取方式，再生成 AI 简报

整理日期：2026-09-11；研究提交：`c8da0e7ece27d6a0007b53f54f546bf0ff1086d4`。

## 一句话说明能力

**Follow Builders 提前设置要关注的平台类型、具体账号 / 节目 / 网站栏目，以及相应的获取和解析方式，再将这些来源的新内容整理成可阅读、可推送、带原文链接的 AI 简报。**

## 本质原理

`预设支持的平台与获取方式 → 配置具体关注对象 → 定期获取 → 解析、过滤、去重 → 宿主 AI 摘要和翻译 → 展示或推送`

| 预设类别 | 关注对象 | 用什么定位 | 对应获取和解析方式 |
| :--- | :--- | :--- | :--- |
| X | 26 个个人或组织账号 | handle，再解析为用户 ID | X API 获取近期动态，提取正文、时间与链接 |
| 播客及 YouTube 观看入口 | 6 个具体节目 | 节目 RSS URL；另有 YouTube 频道或播放列表 URL | RSS 发现节目，pod2txt 获取转录，YouTube 匹配观看链接 |
| 博客网站 | 2 个具体栏目 | 栏目 URL 与文章 URL | 扫描栏目列表，再用站点专用逻辑提取正文 |

播客的内容发现与转录主要依赖 RSS 和转录服务，不能将这一路简单理解为“抓 YouTube 账号并解析视频画面”。完整对象名单见[来源目录](02-sources.md)，一图梳理见[来源图](../assets/source-map.png)。

## 设置和实现的分工

- **来源名单**写在 `config/default-sources.json`，包括账号、RSS 和网站栏目等具体入口。
- **支持的平台和抓取方式**主要由 `generate-feed.js` 中的适配逻辑决定，并非在配置中写入任意网站就能抓取。
- **中心采集端**按预设方式获取内容，发布三个公开 JSON feed；普通客户端消费这些结果。
- **用户偏好**决定语言、篇幅、关注重点和交付方式。普通用户修改本地名单不会改变作者的中心采集范围。
- **新增来源**需确认现有适配器是否支持；自建中心还需切换客户端 feed 地址。具体步骤见[配置指南](03-configuration.md)。

## 与通用采集能力的关系

获取、解析、清洗、去重、存储和展示可以作为共用基础能力；各平台的适配器仍有差异。Follow Builders 的特色主要在作者预先维护的关注名单、简报编辑规则，以及将它们串成低配置成本的阅读流程。

对我们最有价值的是来源如何定制、为什么纳入、实际贡献了哪些研究线索。现有 34 项名单是候选资产，本次没有逐一证明其长期质量。面向开源项目研究，应优先结合原始仓库、版本发布、维护者技术说明、Issues 与可复现使用报告，再用人物动态和节目发现新方向。[来源价值与工具比较](07-source-strategy-and-comparison.md)

## 当前结论的边界

本研究已完成固定源码与公开数据核对，以及准备脚本的 8 项隔离核验；未完成真实采集、模型生成与推送的端到端验证。自动调用模型、历史周报和个人已读状态仍有缺口，详见[核验报告](06-verification.md)。
