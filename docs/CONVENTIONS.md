# 研究项目维护约定

## 编号与顺序

- 项目目录采用 `NNN-slug`，例如 `001-project-name`；短名使用小写英文、数字和连字符。
- 三位编号从 `001` 递增，按收录顺序分配；根 README 索引、图览及未来演示入口均按编号升序排列。
- 新编号取历史已分配最大编号加一。归档项目保留索引，标记为「已归档」，不回收编号。
- 编号与研究进度无关，不因优先级调整重新编号。规模超过 `999` 时，再统一迁移编号宽度和相关链接。

## 新增项目

1. 检查根索引和 `projects/` 中已分配的编号，避免重复。
2. 将整个 `templates/project/` 复制到 `projects/NNN-slug/`。例如首个项目在 PowerShell 中执行：

   ```powershell
   Copy-Item -LiteralPath templates/project -Destination projects/001-project-name -Recurse
   ```

3. 替换项目 README 中的占位信息：编号、名称、原始仓库、研究目标、研究版本等。
4. 将过程记录写入 `notes/`，将截图写入 `assets/`；需要 Web 实践时，在 `web/` 内初始化对应技术栈。
5. 在根 README 中增加索引行。有实际图片后添加图览，有已验证的演示地址后填写演示链接。

示例名称仅用于说明格式，需替换为实际项目名称。

## 信息分工

| 位置 | 维护内容 |
| :--- | :--- |
| 根 README | 一句话摘要、按编号排序的索引、代表性图片、演示入口 |
| 子项目 README | 来源、研究目标、核心结论、运行方式、图片说明和参考资料 |
| 子项目 `notes/` | 源码分析、实验过程、问题排查与专题笔记 |
| 子项目 `assets/` | 封面、截图、架构图，以及素材来源记录 |
| 子项目 `web/` | 可选演示源码、依赖清单和运行说明 |

## 研究状态

统一使用「待研究」「研究中」「已总结」「已归档」。演示情况单独记录为「未部署」「已部署」或「已下线」，不与研究状态混用。根索引没有可访问演示时填写 `—`。

## 图片与说明

- 首张代表图建议命名为 `cover.png` 或 `cover.webp`；其他截图使用描述性英文文件名。
- 根 README 引用 `projects/NNN-slug/assets/文件名`，子项目 README 引用 `assets/文件名`。
- 每张图补充可读的替代文本，正文说明图中展示的功能或结论。
- 在子项目 `assets/README.md` 记录图片说明、来源和必要的许可信息；暂未准备图片时不加入失效图片链接。
- 尽量压缩图片，避免重复提交同一素材；上游代码优先通过仓库链接与提交号定位。

## 更新检查

- 索引编号唯一、升序，项目名称链接能打开。
- 根摘要与子项目研究状态一致，图片路径和图示内容相符。
- 复现说明记录环境、依赖安装、运行命令与已验证结果；未知信息写「待确认」。
- 对上游项目的结论注明研究日期、版本或提交，区分实际验证和推测。
- 已部署演示链接可访问；下线后同步移除索引中的失效入口。
